Fundamentos computacionales
Antes de escribir código necesitas entender cómo funciona el mundo digital: computadoras, redes, sistemas operativos y herramientas del día a día de un desarrollador.

Cómo funciona una computadora
⚙️
Hardware Componentes físicos
  • CPU (procesador) — ejecuta instrucciones, es el "cerebro". Medido en GHz y núcleos
  • RAM (memoria) — almacenamiento temporal y rápido para programas en ejecución
  • Disco duro / SSD — almacenamiento permanente. SSD es mucho más rápido
  • GPU — procesador gráfico; hoy clave también para IA
  • Buses y motherboard — conectan todos los componentes entre sí
🔢
Representación de datos Bits y bytes
  • Bit — la unidad mínima: 0 o 1 (apagado o encendido)
  • Byte — 8 bits. Ejemplo: la letra "A" es el byte 01000001
  • Sistema binario — base 2. Todo en la computadora es binario
  • Hexadecimal — base 16. Más compacto para representar binario
  • ASCII / UTF-8 — estándares para codificar texto en bytes
  • Unidades: KB = 1024 bytes, MB, GB, TB
🖱️
Software de base Sistema operativo
  • ¿Qué es? — software que administra el hardware y permite ejecutar programas
  • Windows / macOS / Linux — los tres principales. Linux domina los servidores
  • Kernel — núcleo del SO; habla directamente con el hardware
  • Procesos e hilos — un programa en ejecución es un proceso; los hilos son tareas dentro de él
  • Sistema de archivos — cómo el SO organiza archivos y carpetas
  • Permisos — quién puede leer/escribir/ejecutar cada archivo
Internet y redes básicas
🌐
Redes Cómo funciona internet
  • IP (Internet Protocol) — dirección única de cada dispositivo en la red
  • DNS — traduce nombres (google.com) a direcciones IP
  • TCP/IP — protocolo que garantiza que los datos lleguen completos y en orden
  • HTTP — protocolo para transferir páginas web. HTTPS es la versión segura
  • Puertos — "puertas" del servidor: 80=HTTP, 443=HTTPS, 22=SSH
  • Router / modem — tu puerta de entrada a internet
↔️
Arquitectura web Cliente y servidor
  • Cliente — tu navegador o app. Hace peticiones (requests)
  • Servidor — computadora que recibe peticiones y responde
  • Request/Response — el ciclo básico de toda comunicación web
  • URL — dirección de un recurso: protocolo + dominio + ruta
  • API — interfaz que expone funcionalidades de un servidor
  • Frontend vs Backend — código del cliente vs código del servidor
Herramientas del desarrollador
💻
Terminal Línea de comandos
  • ¿Qué es? — interfaz de texto para controlar la computadora sin mouse
  • ls / dir — listar archivos
  • cd carpeta — entrar a una carpeta
  • mkdir nombre — crear carpeta
  • cp / mv / rm — copiar, mover, eliminar archivos
  • cat archivo — mostrar contenido de un archivo
  • Rutas relativas vs absolutas — ./ vs /home/user/
📦
Control de versiones Git esencial
  • ¿Para qué? — guardar el historial de cambios de tu código
  • git init — iniciar un repositorio
  • git add . — preparar cambios para guardar
  • git commit -m "mensaje" — guardar los cambios
  • git push — subir a GitHub
  • git pull — descargar cambios del servidor
  • Rama (branch) — línea paralela de desarrollo
✏️
Entorno Editor y productividad
  • VS Code — editor gratuito, extensible, el más usado hoy
  • Extensiones esenciales: Prettier, ESLint, GitLens
  • Markdown — lenguaje de formato para documentación (.md)
  • GitHub — plataforma para alojar repositorios Git
  • Cómo googlear bien — usar site:, "" y operadores de búsqueda
  • Stack Overflow — cómo leer y preguntar correctamente

Fase 1
Programación desde cero
Aprende a pensar como programador: lógica, estructuras de datos y algoritmos. Elige un lenguaje (Python o JavaScript) y no cambies hasta dominar los fundamentos.
⏱ 6–10 semanas Python o JS
💡
Consejo clave: No aprendas syntax de memoria, aprende lógica. La sintaxis la buscarás siempre; el pensamiento lógico no se busca, se desarrolla. Escribe código todos los días aunque sea 30 minutos.
Conceptos fundamentales de programación
📦
Variables y tipos Datos básicos
  • Variable — contenedor con nombre que guarda un valor
  • String — texto entre comillas: "Hola mundo"
  • Integer / Float — números enteros y decimales
  • Boolean — solo true o false
  • Null / undefined — ausencia de valor
  • Tipado dinámico vs estático — JS/Python vs Java/TypeScript
🔀
Control de flujo Decisiones y repetición
  • if / else if / else — ejecutar código según condición
  • switch / match — elegir entre múltiples casos
  • for — repetir N veces o recorrer una lista
  • while — repetir mientras una condición sea verdadera
  • break / continue — salir o saltar en un bucle
  • Operadores: ==, ===, >, <, &&, ||, !
🔧
Funciones Reutilizar lógica
  • Declarar y llamar — definir y ejecutar una función
  • Parámetros — valores de entrada que recibe la función
  • Return — valor que devuelve la función
  • Scope — dónde es visible una variable (local vs global)
  • Funciones anónimas / arrow — const fn = () => {}
  • Recursión — función que se llama a sí misma
// Ejemplo: función recursiva — factorial function factorial(n) { if (n === 0) return 1; // caso base return n * factorial(n - 1); // llamada recursiva } console.log(factorial(5)); // → 120
Estructuras de datos
📋
Colecciones Arrays y objetos
  • Array / Lista — colección ordenada: [1, 2, 3]
  • Objeto / Diccionario — pares clave-valor: {nombre: "Ana"}
  • Métodos de array: push, pop, map, filter, reduce, find
  • Spread operator — [...arr1, ...arr2]
  • Destructuring — const {x, y} = punto
  • Cuándo usar cuál — array para listas, objeto para entidades
🗂️
Estructuras avanzadas Stack, Queue, Map, Set
  • Stack (Pila) — LIFO: último en entrar, primero en salir. Ej: historial del navegador
  • Queue (Cola) — FIFO: primero en entrar, primero en salir. Ej: cola de impresión
  • Map — como objeto pero keys pueden ser cualquier tipo
  • Set — colección sin duplicados
  • Árbol binario básico — nodos con hijos izquierdo y derecho
  • Linked List — nodos que apuntan al siguiente
📊
Complejidad Big O Notation
  • O(1) — constante: acceder a un elemento por índice
  • O(log n) — logarítmico: búsqueda binaria
  • O(n) — lineal: recorrer un array completo
  • O(n²) — cuadrático: dos bucles anidados (evitar en datos grandes)
  • Tiempo vs espacio — tradeoff entre velocidad y memoria
  • Por qué importa — código lento puede ser inutilizable con muchos datos
Algoritmos esenciales
🔍
BúsquedaEncontrar datos
  • Búsqueda lineal — recorrer elemento por elemento. O(n)
  • Búsqueda binaria — en datos ordenados, divide a la mitad. O(log n)
  • BFS (amplitud) — explorar por niveles en un árbol/grafo
  • DFS (profundidad) — explorar hasta el fondo antes de retroceder
↕️
OrdenamientoOrganizar datos
  • Bubble Sort — el más simple, el menos eficiente. O(n²)
  • Merge Sort — divide y ordena mitades. O(n log n)
  • Quick Sort — elige un pivote y particiona. O(n log n) promedio
  • Array.sort() — en JS/Python ya incluido; úsalo en producción
🧩
TécnicasEstrategias de resolución
  • Divide y vencerás — partir problema grande en subproblemas
  • Programación dinámica — guardar resultados para no recalcular
  • Greedy (voraz) — elegir la mejor opción local en cada paso
  • Two pointers — dos índices que se mueven para resolver en O(n)

Frontend — la parte visual
Construye todo lo que el usuario ve e interactúa. HTML estructura, CSS embellece, JavaScript anima, y React hace todo escalable.
⏱ 8–12 semanas HTML → CSS → JS → React
⚡
Orden importa: HTML nativo → CSS puro → JS vanilla → React. Muchos saltan a React sin saber el DOM y luego no entienden lo que hace el framework.
HTML — estructura de la web
📄
HTMLEtiquetas y estructura
  • Etiquetas semánticas: <header>, <nav>, <main>, <article>, <footer>
  • Encabezados: <h1> a <h6> — jerarquía de títulos
  • Texto: <p>, <span>, <strong>, <em>
  • Listas: <ul>, <ol>, <li> — desordenadas y ordenadas
  • Links e imágenes: <a href="">, <img src="" alt="">
  • Formularios: <form>, <input>, <button>, <select>
  • Tablas: <table>, <tr>, <td>, <th>
  • Accesibilidad: atributos alt, aria-label, role
🔗
HTML avanzadoFormularios y multimedia
  • Tipos de input: text, email, password, number, date, checkbox, radio
  • Validación HTML5: required, pattern, min, max
  • Audio y video: <video>, <audio> con controles

  • Meta tags: charset, viewport, description para SEO

CSS — estilos y diseño
📦
CSS fundamentosBox model y selectores
  • Box model — todo elemento es una caja: content + padding + border + margin
  • Selectores: clase (.btn), ID (#hero), elemento (p), combinados
  • Especificidad — qué regla gana cuando hay conflicto
  • Display: block, inline, inline-block, none
  • Position: static, relative, absolute, fixed, sticky
  • Colores: hex, rgb(), hsl(), variables CSS
  • Tipografía: font-family, size, weight, line-height
🗺️
CSS LayoutFlexbox y Grid
  • Flexbox — layout en una dimensión (fila o columna)
  • justify-content, align-items, flex-wrap, gap
  • CSS Grid — layout en dos dimensiones (filas Y columnas)
  • grid-template-columns, grid-area, repeat(), minmax()
  • Cuándo usar cuál: Flex para componentes, Grid para páginas
  • Media queries: cambiar estilos según el ancho de pantalla
  • Mobile-first: diseñar primero para móvil, luego ampliar
✨
CSS modernoVariables y animaciones
  • Variables CSS: --mi-color: #fff; y var(--mi-color)
  • Transiciones: transition: all 0.3s ease;

  • Pseudo-clases: :hover, :focus, :nth-child, :not()
  • Pseudo-elementos: ::before, ::after
  • Tailwind CSS — clases utilitarias; alternativa a CSS manual
JavaScript en el navegador
🌳
DOMManipular el HTML
  • DOM — árbol de objetos que representa el HTML de la página
  • document.querySelector('.clase') — seleccionar elementos
  • element.textContent = 'nuevo texto' — cambiar contenido
  • element.style.color = 'red' — cambiar estilos
  • element.classList.add/remove/toggle — manejar clases
  • document.createElement / appendChild — crear nodos dinámicamente
🖱️
EventosInteractividad
  • addEventListener('click', fn) — escuchar acciones del usuario
  • Tipos: click, keydown, submit, scroll, resize, load
  • Event object — info del evento: event.target, event.key
  • event.preventDefault() — evitar comportamiento por defecto
  • Event delegation — escuchar en el padre, actuar en hijos
  • Debounce / throttle — controlar frecuencia de eventos
🔄
Async JSOperaciones asíncronas
  • Callbacks — función que se llama cuando termina algo. El origen
  • Promesas — objeto que representa un valor futuro
  • .then().catch().finally() — encadenar promesas
  • async/await — sintaxis más legible para promesas
  • fetch('url') — hacer peticiones HTTP desde el navegador
  • try/catch — manejar errores en código asíncrono
React y Next.js
⚛️
React coreComponentes y estado
  • Componente — función que retorna JSX (HTML dentro de JS)
  • Props — datos que el padre pasa al hijo (de solo lectura)
  • useState — estado local que al cambiar re-renderiza el componente
  • useEffect — efectos secundarios: fetch, timers, subscripciones
  • useRef — referencia a un elemento del DOM
  • useContext — compartir datos sin pasar props anidadas
  • Virtual DOM — React compara el DOM real vs virtual para minimizar cambios
🚀
Next.jsReact en producción
  • ¿Por qué Next? — routing automático, SSR, SSG, API routes incluidas
  • App Router — sistema de rutas basado en carpetas (Next 13+)
  • SSR vs SSG vs CSR — renderizado en servidor, build-time o cliente
  • Server Components — componentes que corren solo en el servidor
  • API Routes — crear endpoints backend dentro del proyecto Next
  • Image y Link — componentes optimizados para rendimiento
  • Metadata — SEO desde el código de servidor

Fase 3
Backend — el servidor
Aquí vive la lógica del negocio, la seguridad y la base de datos. Aprende a crear APIs REST, manejar autenticación y conectar con PostgreSQL.
⏱ 8–12 semanas Node.js + Express + PostgreSQL
🔑
Aquí te conviertes en Full Stack. Un buen backend es seguro, rápido, y bien documentado. Aprende primero sin ORM (SQL puro) para entender lo que el ORM hace por ti.
HTTP y APIs REST
📡
HTTP en profundidadMétodos y cabeceras
  • GET — obtener datos (sin modificar nada)
  • POST — crear un recurso nuevo
  • PUT / PATCH — actualizar completo / parcial
  • DELETE — eliminar un recurso
  • Status codes: 200 OK, 201 Created, 400 Bad Request, 401 No auth, 404 Not found, 500 Server error
  • Headers: Content-Type, Authorization, CORS headers
  • Body y params: JSON en body, query strings, URL params
🏗️
REST APIsDiseño de endpoints
  • Recursos: /users, /products, /orders — sustantivos, no verbos
  • CRUD: GET /users (lista), GET /users/:id, POST /users, PUT /users/:id, DELETE /users/:id
  • Anidamiento: /users/:id/orders
  • Paginación: ?page=2&limit=20
  • Filtros y búsqueda: ?status=active&q=juan
  • Versionado: /api/v1/users
Node.js y Express
🟢
Node.jsJS en el servidor
  • ¿Qué es Node? — V8 de Chrome corriendo JS fuera del navegador
  • Event loop — cómo Node maneja múltiples peticiones sin bloquear
  • Módulos: CommonJS (require) y ESM (import)
  • npm / pnpm — gestores de paquetes. package.json
  • fs, path, os — módulos nativos de Node para archivos y sistema
  • process.env — variables de entorno. Nunca hardcodear secretos
🚂
Express.jsFramework web
  • Router — organizar rutas por recurso en archivos separados
  • Middleware — funciones que procesan request antes de llegar al handler
  • Controller — función que maneja la lógica de un endpoint
  • Validación: zod o express-validator para validar inputs
  • Error handling: middleware de error con 4 parámetros
  • CORS: configurar qué orígenes pueden consumir la API
🔒
AutenticaciónSeguridad de usuarios
  • Hashing: bcrypt para guardar contraseñas (nunca texto plano)
  • JWT — token firmado que viaja en el header. Sin estado en el servidor
  • Refresh tokens — token de larga duración para renovar JWT
  • OAuth 2.0 — login con Google/GitHub. Flujo Authorization Code
  • Sessions — alternativa a JWT; estado en servidor con cookie
  • Rate limiting — limitar peticiones por IP para evitar abuso
Bases de datos
🗃️
SQL — PostgreSQLBases de datos relacionales
  • Tabla — colección de filas con columnas tipadas
  • Primary key — identificador único por fila (uuid o serial)
  • Foreign key — columna que referencia otra tabla
  • SELECT * FROM users WHERE active = true ORDER BY name
  • JOIN — combinar datos de múltiples tablas
  • Índices — acelerar búsquedas frecuentes
  • Transacciones — agrupar operaciones para que sean atómicas
  • Migraciones — versionar cambios al esquema de la BD
⚡
ORM — PrismaBD con TypeScript
  • ORM — Object Relational Mapper: trabaja con objetos en vez de SQL
  • Schema Prisma — definir modelos en schema.prisma
  • prisma.user.findMany() — consultar con tipo seguro
  • prisma.user.create({ data: {...} }) — insertar
  • Relaciones: include: { posts: true }
  • Cuándo NO usar ORM — queries muy complejos; mejor SQL puro
🔥
SupabaseBackend como servicio
  • ¿Qué es? — PostgreSQL + Auth + Storage + Realtime en la nube
  • Auth integrado — login con email, Google, GitHub sin código de servidor
  • Row Level Security — cada usuario solo ve sus datos a nivel BD
  • Storage — subir archivos (imágenes, PDFs) con permisos
  • Realtime — suscribirse a cambios en la BD con WebSockets
  • Edge Functions — serverless functions en Deno

Fase 5
Ingeniería de sistemas
Los temas que separan a un junior de un senior: diseño de sistemas escalables, redes, seguridad y buenas prácticas de código.
⏱ Continuo Estudio en paralelo con proyectos
🎯
Estos temas se aprenden construyendo. Estudia la teoría y aplícala en tus proyectos reales. No tiene sentido memorizar patrones de diseño sin haberlos necesitado antes.
Diseño de sistemas (System Design)
📐
EscalabilidadDiseñar para crecer
  • Escalar vertical — máquina más potente (límite físico)
  • Escalar horizontal — más máquinas en paralelo (sin límite teórico)
  • Load Balancer — distribuye tráfico entre servidores
  • Caching — guardar resultados frecuentes en Redis para no recalcular
  • CDN — servir archivos estáticos desde el servidor más cercano al usuario
  • Database sharding — dividir la BD en múltiples instancias
🏗️
ArquitecturaMicroservicios vs monolito
  • Monolito — todo en una app. Ideal para empezar. Fácil de debuggear
  • Microservicios — servicios pequeños independientes. Complejidad alta
  • API Gateway — punto de entrada único que enruta a microservicios
  • Message queues — RabbitMQ/Kafka para comunicación asíncrona
  • CAP Theorem — no puedes tener consistencia, disponibilidad y tolerancia a partición a la vez
  • Event-driven — servicios que reaccionan a eventos en vez de llamadas directas
Redes y protocolos en profundidad
🌐
Modelo OSILas 7 capas
  • Capa 1 — Física: cables, señales eléctricas
  • Capa 2 — Enlace: MAC address, switches
  • Capa 3 — Red: IP, routers, enrutamiento
  • Capa 4 — Transporte: TCP (confiable) vs UDP (rápido)
  • Capa 5-6 — Sesión/Presentación: TLS/SSL, cifrado
  • Capa 7 — Aplicación: HTTP, DNS, SMTP, FTP
⚡
Protocolos modernosHTTP/2, WebSockets, gRPC
  • HTTP/2 — múltiples requests en una conexión (multiplexing)
  • HTTP/3 / QUIC — basado en UDP, más rápido en redes inestables
  • WebSockets — conexión bidireccional persistente (chats, juegos)
  • SSE (Server-Sent Events) — servidor manda eventos al cliente (notificaciones)
  • gRPC — RPC binario de alto rendimiento entre microservicios
  • GraphQL — alternativa a REST que el cliente controla qué pide
Seguridad de aplicaciones
🛡️
OWASP Top 10Vulnerabilidades comunes
  • SQL Injection — inyectar SQL malicioso en inputs. Prevención: queries parametrizados
  • XSS (Cross-Site Scripting) — inyectar JS en páginas ajenas. Prevención: sanitizar outputs
  • CSRF — acción no autorizada en nombre del usuario. Prevención: tokens CSRF
  • Broken Authentication — sesiones mal implementadas o tokens débiles
  • Insecure Direct Object Reference — acceder a recursos de otros por ID predecible
  • Security Misconfiguration — defaults inseguros, errores expuestos en prod
🔑
Buenas prácticasCódigo seguro
  • Principio de mínimo privilegio — dar solo los permisos necesarios
  • Validación de inputs — nunca confiar en datos que vienen del cliente
  • HTTPS siempre — sin excepciones en producción
  • Secretos en variables de entorno — nunca en el código fuente
  • Dependencias actualizadas — vulnerabilidades en librerías son comunes
  • Logs sin datos sensibles — no loggear contraseñas ni tokens
Calidad de código y buenas prácticas
📏
Clean CodeCódigo legible
  • Nombres significativos — getUserById no fn2
  • Funciones pequeñas — una función, una responsabilidad
  • DRY (Don't Repeat Yourself) — no copiar y pegar código
  • YAGNI — no implementar lo que no necesitas todavía
  • Comentarios útiles — comentar el "por qué", no el "qué"
  • Code review — otro par de ojos siempre mejora el código
🧪
TestingCódigo que no se rompe
  • Unit tests — probar una función aislada. Vitest / Jest
  • Integration tests — probar que partes del sistema funcionan juntas
  • E2E tests — simular acciones del usuario en el navegador. Playwright
  • TDD — escribir el test antes del código
  • Mocking — simular dependencias externas (BD, APIs)
  • Coverage — porcentaje del código cubierto por tests
🎨
Design PatternsSoluciones probadas
  • Singleton — una sola instancia de una clase (conexión a BD)
  • Observer — notificar a múltiples suscriptores cuando algo cambia
  • Factory — crear objetos sin especificar la clase exacta
  • Repository — capa de abstracción entre lógica y BD
  • SOLID principles — 5 principios de diseño orientado a objetos
  • MVC / MVVM — patrones para separar datos, lógica y vista

Fase 6
Conseguir trabajo
Portafolio, entrevistas técnicas y cómo entrar al mercado. Tres proyectos sólidos valen más que treinta proyectos mediocres.
⏱ 2–4 meses Portafolio + LeetCode + LinkedIn
🏆
La clave: Código público funcionando en producción. Un reclutador que ve tu app desplegada y tu repositorio limpio te considera antes que a alguien con más cursos pero sin proyectos.
Portafolio que impresiona
🛠️
ProyectosQué construir
  • Proyecto 1 — Full Stack con auth: app con login, roles, CRUD completo. Ejemplo: gestor de tareas o blog con usuarios
  • Proyecto 2 — API REST documentada: backend con Swagger/OpenAPI, tests, manejo de errores
  • Proyecto 3 — Algo tuyo: resuelve un problema real que tú tengas. Lo más memorable en entrevistas
  • Desplegado: URL funcionando. Sin esto no existe
  • README excelente: qué hace, cómo instalarlo, screenshots, tecnologías
🌐
Presencia onlineSer encontrable
  • GitHub activo — commits regulares, perfil con README propio, green squares
  • LinkedIn optimizado — foto profesional, headline con skills, proyectos visibles
  • Portfolio web propio — una página simple con tus proyectos y contacto
  • Twitter/X técnico — opcional pero ayuda al networking
  • Blog técnico — escribir sobre lo que aprendes demuestra profundidad
Entrevistas técnicas
🧮
AlgoritmosLeetCode y resolución
  • Objetivo: 50-75 problemas fáciles/medios son suficientes para la mayoría de empresas
  • Patterns esenciales: Two Pointers, Sliding Window, BFS/DFS, Dynamic Programming básico
  • Neetcode 150 — lista curada, la más eficiente para prepararse
  • Hablar mientras resuelves — el proceso importa tanto como la respuesta
  • Preguntar aclaraciones — siempre antes de empezar a codear
💬
Entrevistas técnicasPreguntas comunes
  • JS: event loop, closures, promises vs async/await, prototypes, this
  • React: ciclo de vida, virtual DOM, hooks, state vs props, memoización
  • Backend: REST vs GraphQL, auth, SQL vs NoSQL, indexación
  • System Design (juniors): diseñar un URL shortener, un chat simple
  • Git: merge vs rebase, cómo resolver conflictos, cherry-pick
🤝
BehavioralPreguntas de comportamiento
  • Método STAR: Situación, Tarea, Acción, Resultado
  • "¿Cuéntame de un bug difícil que resolviste?"
  • "¿Cómo manejas plazos apretados?"
  • "¿Cómo aprendes tecnologías nuevas?"
  • "¿Cuál ha sido tu mayor fracaso profesional?"
  • Ten preguntas para ellos — siempre pregunta sobre el equipo y proceso
